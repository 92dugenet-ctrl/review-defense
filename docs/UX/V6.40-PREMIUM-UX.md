# Review Defense V6.40 — Premium UX implementation

## Source of truth

This document codifies the V6.40 UX work completed for the application console.

### Visual direction

- White-first interface.
- Review Defense blue as the primary action and focus color.
- Very light blue surfaces for contextual information.
- White cards with subtle borders and restrained shadows.
- Generous whitespace and strong typographic hierarchy.
- No dark/cyber/military visual language.
- Semantic status colors only; color is never the only state signal.
- Desktop-first, with a dedicated mobile behavior rather than a shrunken desktop layout.

## Information architecture

Primary user journey:

**Vue d’ensemble → Avis → Dossiers → Preuves → Validation humaine → Préparation → Résultat**

Supporting operational areas:

- Charge & SLA
- Escalations
- Alertes
- Journal
- Organisation

The application should make the next human action obvious without exposing unnecessary technical vocabulary.

## Dashboard

The dashboard answers, in order:

1. Combien ?
2. Quoi ?
3. Pourquoi ?
4. Que dois-je faire ?

The page prioritizes attention items and operational state over decorative KPI density.

## Dossiers

A dossier is the core product object.

The workspace exposes:

- source review;
- structured claims;
- evidence;
- evidence ↔ claim matrix;
- contradictions / verification signals;
- readiness;
- timeline;
- decision gate;
- next action.

The visible workflow remains:

**Analyse → Preuves → Validation → Préparation → Résultat**

## Human validation

Validation is a signature-like human decision point.

The UI must show:

- what was analysed;
- what evidence supports the decision;
- what remains uncertain;
- the current state;
- what the validation authorizes.

No UI may imply that Google or another external platform is acted upon automatically.

## Preparation versus execution

The submission area explicitly distinguishes:

**Préparation terminée ≠ action externe exécutée**

The existing product safety boundary remains:

**Decision → Freeze → Human Approval → Controlled Preparation/Submission**

## Micro-UX

Required states:

- skeleton loading;
- action loading without layout jumps;
- success toast;
- human-readable errors;
- actionable empty states;
- visible active filters;
- permission boundaries;
- frozen-case explanation;
- already-validated explanation;
- double-submit protection;
- autosave feedback where applicable;
- reduced-motion support.

## Accessibility and responsive behavior

- visible keyboard focus;
- logical keyboard navigation;
- contextual form errors;
- accessible labels for icon-only actions;
- contrast-conscious semantic colors;
- no color-only state communication;
- reduced motion;
- touch-friendly mobile actions;
- tables become readable cards/stacked content on small screens;
- critical mobile validation actions remain reachable.

## Implementation note

The V6.40 visual implementation is intentionally layered over the existing functional console. The product architecture and safety boundary are unchanged.
